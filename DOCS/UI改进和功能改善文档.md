## 1. 改善目标

让 DBA 在打开文件后能迅速回答四个问题：正在看哪个事件/语句、输入提供了哪些事实、最值得调查的问题是什么、建议需要什么验证才能应用。优先保证结论与指标正确，然后降低定位和比较所需操作量。

当前已有死锁/计划/A-B 三个工作区，Nodify 图、传统树、XML、SQL diff、索引沙盒、历史快照和导出。导航栏工作树已经增加中文提示、AutomationProperties.Name，以及 Ctrl+O、Ctrl+Shift+O、Ctrl+R、Ctrl+Shift+C、Ctrl+L、F1。改善应复用这些能力，避免再次实现同一功能。

## 3. 目标信息架构

建议保留三类工作区，但把“当前文件/快照/事件/语句”提升为公共上下文栏。主工作区显示图和问题，XML、统计、完整属性作为按需打开的证据视图。

```text
┌ 文件名 / 快照名 ─ 类型 ─ 捕获时间 ─ 输入能力 ─ [打开] [导出] ┐
│ [死锁] [执行计划] [比较]                                     │
├ 事件或语句选择 ────────────────────── 搜索/过滤 ────────────┤
│ 对象/问题列表       │ 图或比较画布             │ 证据详情     │
│ 严重度与置信度      │ 选中节点、关联边          │ 事实         │
│ 可折叠             │ 自适应、缩放、定位        │ 可能原因     │
│                    │                         │ 验证/建议    │
├ 已分析 / 已跳过 / 失败 ─ 当前阶段 ─ [取消] ─────────────────┤
└ 可展开：SQL / 原始 XML / 统计 / 改写差异                      ┘
```

“输入能力”示例：`实际计划 · 有行数 · 无运行耗时 · 无完整统计直方图`。未知能力显示“输入未提供”，避免空白让用户猜测。文件路径默认显示文件名，完整路径放 tooltip/详情，兼顾空间与共享截图中的隐私。

如果继续使用现有 DocumentTabViewModel，应将其与可见文档选择联动；不要仅在模型维护 Tabs，而由多个 Current* 字段分别代表当前文档。跨工作区切换时明确保留图选择、展开状态和筛选条件。

## 4. 执行计划工作区

### 4.1 首屏顺序

建议从上到下为：文档能力 → 语句选择 → 诊断摘要 → 算子图与证据。

语句选择列出 Batch/Statement 序号、SQL 摘要、估算成本和问题数；同名 NodeId 在不同语句下独立定位。默认可以定位问题优先级较高的语句，但必须显示已选中的语句及总数，不默默只分析首条。此功能依赖 R16 和领域身份模型。

摘要应显示 `3 个需调查问题 / 2 个提示 / 4 条规则因缺少运行信息跳过`，而不是“完美通过”或“已发现 N 个硬伤”。严重度和置信度是两列：高影响的低置信度假设不应伪装成已确认的根因。

### 4.2 问题列表与证据抽屉

每个问题卡固定包含标题、严重度、置信度、语句/节点、关键数值和一个主要操作“定位证据”。展开后再展示可能原因、建议和官方来源。

```text
基数估计偏差                 警告 · 已观察到
语句 2 / Node 7              估算输出 100，实际输出 25,000
[定位节点] [查看计数口径]

证据：线程计数、执行次数、XML 位置
可能原因：相关列分布、参数敏感、表达式或统计信息质量
下一步：比较参数与统计证据；确认是否属于重复执行
建议：提供检查步骤，按适用条件评估变更
```

示例数字仅用于线框展示。点击节点反向过滤问题列表；点击问题定位节点并展开相关属性，避免用户在长报告和大图之间搜索 NodeId。复制结果带语句、节点、指标单位和证据来源。

### 4.3 图节点的信息层级

默认节点显示算子名、对象摘要、实际/估算输出、一个最高优先级问题标记。运行模式、排序、分区、线程、谓词等放在详情；远景缩放只显示算子和风险标记，近景再增加数值。

图工具栏建议显示“适应窗口”“100%”“定位选中”“折叠/展开子树”和查找。现有缩放、拖动、折叠能力应复用；为布局选项提供可理解名称，如“从右向左数据流”“自上而下”，把 Nodify、Recosting 等实现词移出主要导航。

### 4.4 指标表与单位

| 用户看到的名称 | 数据来源 | 无数据时 |
| --- | --- | --- |
| 估算输出行数 | EstimateRows，保留计数作用域 | N/A |
| 实际输出行数 | ActualRows，标明线程/执行聚合方式 | 输入未提供 |
| 实际读取行数 | ActualRowsRead | 输入未提供 |
| 实际执行次数 | 原始线程计数及明确派生定义 | N/A |
| 估算自身成本 / 估算子树成本 | 分开列示 | N/A |
| 运行耗时 | ActualElapsedms，明确节点/线程口径 | 输入未提供 |
| 执行模式 | ActualExecutionMode / EstimatedExecutionMode | Unknown，并标明估算/实际 |

保留原始精度，默认格式化为可读数；tooltip 提供原值。百分比应标明分母是当前语句、整个 batch 还是模型权重。禁止以读取行数替代输出行数，也禁止把未知运行指标显示为零。

### 4.5 SQL、XML 与统计信息

SQL 编辑区分“原始输入（只读）”和“候选改写”，通过 diff 对照。XML 视图支持按节点定位、复制路径和查找；大文件延迟加载完整文本，避免首屏同时复制多份字符串。

统计信息显示“来源、最后更新时间、样本行、总行数、修改计数、是否确有直方图”。执行计划里的统计使用信息不等于完整直方图；缺失时提供离线导入入口说明，避免用示意数据冒充真实分布。参数与统计风险按当前语句归属展示，不让另一条语句的数据提升本语句严重度。

## 5. 死锁工作区

### 5.1 事件列表

XEL 入口已有事件读取和选择能力，建议扩展成可搜索列表：捕获时间（含时区）、事件序号、参与进程数、受害者、数据库和资源类型摘要。多 deadlock 包装 XML 也使用同一列表。

支持按时间、数据库、资源类型过滤，选择事件后更新图、详情与报告。相同模式的事件可以按指纹聚合，用户可进入某次原始事件核查；不能仅按 SPID 聚合，因为 SPID 会复用。

### 5.2 进程与资源详情

进程列表建议显示 SPID/ECID、受害者标记、隔离级别、priority、logused 和等待摘要。登录名/主机名默认折叠，用户按需查看。资源列表保留原始资源 ID、对象身份、锁模式、requestType 和类型特有属性。

选择一条等待边时用自然语言说明：`会话 A 请求资源 R 的 X 锁；会话 B 当前持有 S 锁`，同时列出原始字段。不把请求者与持有者的任意 S/X 组合自动解释为“转换锁”，不把 PAGE/RID 直接解释为已发生页分裂。

Exchange/SyncPoint 资源应显示不同于普通锁的详情。具体字段的支持边界可以依据 [KB4089473](https://support.microsoft.com/en-us/topic/kb4089473-better-intra-query-parallelism-deadlocks-troubleshooting-in-sql-server-2017-and-2016-c0cc8ac0-ae4f-966a-b6ed-29dfcd17972a) 标注；未知字段仍允许查看原 XML。

### 5.3 依赖推演

将现有播放模式改名为“依赖推演”，始终显示“依据死锁快照生成，步骤不代表实际发生时间”。播放速度表示动画速度；Grant/Request 文案描述捕获时的持有/等待关系。不要把数字步骤解释为 SQL Server 事件序号。

“聚焦关键环”应共享主图的循环成员集合，先修复 R08；多环时显示环选择和所含进程/资源。修复 R18 后才展示去重环数。受害者标记使用图标、文字和颜色三种线索，不能只依赖红色。

### 5.4 诊断与建议

分成三组：

1. **确认事实**：资源模式、等待关系、受害者、参数/事务字段。
2. **可能模式**：访问顺序交叉、范围锁、查询内部并行等；说明匹配证据及缺失条件。
3. **建议与验证**：缩短事务、统一访问顺序、检查索引、评估行版本等；每项都带适用范围。

RCSI、UPDLOCK、ROWLOCK、MAXDOP 和填充因子应附条件和代价，不能承诺一次调整消除所有死锁。若证据不足，优先给出“还需要哪些数据”，而不是增加确定语气。

## 6. A/B 比较工作区

保留当前历史、设为 A/B、交换和保存会话功能，但增加可见按钮“设为基准 A”“设为候选 B”，降低只通过右键菜单发现功能的成本。历史项显示快照来源、时间和计划类型。

比较前给出摘要：语句匹配、参数是否相同、实际/估算类型、引擎版本/兼容级别可见情况。条件未知时允许结构比较，运行指标差值显示 N/A。

| 比较内容 | UI 规则 |
| --- | --- |
| 估算成本 | 标为“估算成本变化”；不显示成性能百分比 |
| 实际耗时/逻辑读取 | 两边均存在且口径一致时展示差值 |
| 算子结构 | 显示新增、删除、变化、未匹配及匹配可信度 |
| 语句覆盖 | 显示已比较 x/y 条；未匹配语句可选择 |
| 运行环境差异 | 作为解释上下文，不能直接推出因果 |

提供“仅看变化”“同步定位”“上一处/下一处差异”；没有变化时准确写“当前匹配范围内未发现所选指标变化”。B 是候选，不预先标注“优化后”。

## 7. SQL 改写审核

默认展示建议清单，用户可逐条启用。每项包括规则、原文/候选、影响范围、前提、语法校验、语义校验状态。语法通过与结果等价使用不同标记。

```text
候选改写 2/5       语法校验：通过       语义等价：未验证
删除 LTRIM
前提：目标列不含需要保留语义的前导空格
当前证据：未提供列约束/数据验证
[ ] 纳入候选 SQL
[查看 diff] [复制验证步骤]
```

R02/R19 类改写默认不选中。所有警告从 RefactorContext 保留到 UI，不只传 OutputSql。支持撤销选择和恢复原文；“复制候选 SQL”与“保存新文件”分开。覆盖原文件时必须满足 R03 的备份和原内容校验，而不是依靠反复确认框弥补底层缺陷。

用户取消任一候选不影响其他已验证候选；最终报告记录实际选择的规则、条件和校验状态。工具不默认连接生产库执行改写。

## 8. 缺失索引与沙盒

索引卡首先显示完整 Database.Schema.Table、来源语句、Equality/Inequality/Include 列、原始 Impact；其次展示本工具评分及解释。列表支持同对象候选合并查看，但在缺少现有索引定义时不声称已经完成重复索引检测。

沙盒将“预估总成本降低 x%”改为明确的模型输出或候选影响说明，修复 R12 前不作为排序依据。对 Seek/Scan、覆盖、排序消除等结论分别标明“证据支持”“假设”“无法判断”。现有 Tipping Point 文字中的“始终”“将选择”改成带条件的可能性描述。

DDL 页显示目标对象、命名、键顺序、包含列和选项。ONLINE、压缩、MAXDOP、SORT_IN_TEMPDB 按版本/环境说明适用条件；没有版本数据时显示待确认。复制部署包前可查看 DDL 与回滚说明，R13/R14 必须先修复。

验收重点为对象和语义正确，而不是让模拟数字看起来更精确。Microsoft 明确将缺失索引建议作为索引分析的一项输入，不能原样视为必需部署项。[官方说明](https://learn.microsoft.com/en-us/sql/relational-databases/indexes/tune-nonclustered-missing-index-suggestions)

## 9. 任务状态、错误与恢复

| 状态 | 显示 | 可执行操作 |
| --- | --- | --- |
| 空白 | 支持格式、打开入口、示例说明 | 打开/拖放 |
| 加载/解析 | 文件名、当前阶段、已读事件数或已识别节点数 | 取消；允许打开另一文件并使旧请求过期 |
| 分析 | 已完成规则数与可用能力 | 取消 |
| 准备视图 | 已分析，正在构建图形 | 取消或先看文本摘要 |
| 部分成功 | 可用结果、失败/跳过项和原因 | 查看详细错误、重试相关阶段 |
| 不支持/格式错误 | 检测到的类型、错误位置、支持方式 | 换文件/复制不含敏感原文的错误摘要 |
| 就绪 | 当前文件、语句/事件数、问题/跳过计数 | 定位、比较、导出 |

状态不使用伪造百分比；文件读取失败不残留上一文件的成功提示。过期请求不得改变新文档的标题、图、状态或错误弹窗。清空结果提供可恢复的轻量操作；是否需要保留调优历史应在产品行为中明确。

## 10. 布局、视觉与可访问性

### 10.1 布局建议

用 Grid/模板管理标签，不依赖负 Margin。侧栏宽度可调且可折叠，保存用户设置。建议以 WPF DIP 作为断点：

- 宽窗口：列表、画布、证据三栏同时显示。
- 中等窗口：保留画布和一侧栏，另一侧变可切换抽屉。
- 窄窗口：在问题、图、证据之间切换，主任务按钮保持可达。

具体断点应通过 1280×720、1366×768、1920×1080 和 125%/150%/200% 缩放验证后确定；上述是测试矩阵，不是已测结果。避免同时设置多个刚性 MinWidth 使整个窗口横向挤出。

### 10.2 视觉规范建议

正文建议 13–14 DIP，辅助文字不承担唯一关键信息；数字使用对齐格式。颜色全部从语义资源取得，例如 Surface、TextPrimary、TextSecondary、Warning、Critical、Selection。深色模式不保留仅为浅色设计的白色卡片。

严重度用图标、文字及颜色共同表达；连接线选中状态增加线型/宽度而非只变颜色。节点 hover tooltip 提供摘要，但所有关键信息也必须能通过键盘选中后在详情读到。

把普通文本对比度至少 4.5:1 作为视觉验收目标，大号文字至少 3:1；这是参照 WCAG 的设计门槛，不声称本 WPF 应用已取得任何合规认证。[对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

### 10.3 键盘和辅助技术

保留已实现的六组快捷键，增加可见的快捷键帮助。新的查找、图导航、展开、定位命令应在明确的焦点范围内生效。输入控件保留编辑按键行为，普通命令的 CanExecute 跟随文档状态。

为图节点和边提供可读名称，如“语句 2，Node 7，Index Seek，警告 1 项”；自定义控件通过 AutomationPeer 提供语义。Tab 顺序、方向键选择、Enter 查看详情、Escape 关闭抽屉要一致，关闭抽屉后焦点返回触发按钮。播放和大型绘图提供减少动画选项。

## 12. 分期落地

第一期修正指标、输入状态、关键风险文案和高风险改写默认行为；复用现有控件，优先解决“看错、用错”。第二期完成语句选择、问题列表、证据抽屉和可靠 A/B；以统一模型为前提。第三期再推进 XEL 聚合、配置界面、大图优化和高级可访问性。

每期交付应包含具体场景截图、键盘任务记录、输入夹具及未支持能力清单。不能用界面美化替代 R01–R22 的正确性修复，也不能用测试总数替代用户任务是否能完成的验证。
