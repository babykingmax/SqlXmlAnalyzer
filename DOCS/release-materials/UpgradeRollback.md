# 升级与回退操作单

此操作单只处理本地安装文件、配置、会话和 SQL 文件。**回退应用版本不会撤销用户已执行到数据库中的 SQL、DDL、数据修改或外部副作用。** 数据库恢复应使用 DBA 审核的事务、迁移回退脚本或数据库备份，并在对应环境验证。

## 升级前

1. 关闭现有 GUI/CLI，保存会话。记录现有 EXE、全部依赖、配置、会话及原 SQL 的路径和 SHA-256；保留现有安装的完整副本。不能把当前候选复制一份并标作“上一版本”。版本号相同时用 Git 源版本及二进制 hash 区分。
2. 把旧安装、升级前配置/会话、IMP-19 写回产生的原 SQL 备份存放在独立、仅授权用户可读写的备份目录。记录每份备份与原文件的映射及哈希，停止其他写入者后再备份。诊断数据包不充当此备份。
3. 在可信源仓库的 PowerShell 7.4 或更新进程中加载已构建的 Core，封存目录；把返回的清单 SHA-256 独立存档，不只保存在备份内部：

```powershell
[Reflection.Assembly]::LoadFrom((Resolve-Path 'bin/Release/net8.0-windows/SqlXmlAnalyzer.Core.dll'))
[SqlXmlAnalyzer.Core.Release.ReleaseBundle]::Seal('E:/Recovery/before-upgrade', 'before-upgrade-20260910', 'recovery')
```

4. 核对候选清单的 SHA-256 与可信交付记录，并用 `ReleaseBundle.Verify(目录, SHA256)` 验证全套文件。哈希用于完整性检查，不是数字签名；不要运行来源不可信的工具或包。

## 安装与验收

1. 将完整候选恢复/复制到新的版本目录。使用该目录的 GUI 和 CLI，先打开测试计划、死锁文件，选择语句/事件，审核后导出到新文件。检查程序目录的配置和原生依赖。
2. 从升级前配置、会话的副本读取；如需迁移，只另存新名称。对比有效规则设置、A/B 计划和原 SQL 哈希。原 SQL 的实际应用必须经过工具的审核/验证/备份流程。
3. 按 `IssueStatus.md` 确认范围，保留候选 ID、构建/测试记录、日志、导出样例和剩余问题。脚本打包成功不是正式发布批准；未完成项不得改记关闭。

## 回退演练与执行

1. 关闭候选，保留候选期间新生成的会话和 SQL，避免退回时丢失新工作。不要让两个版本同时写同一份用户文件。
2. 在源仓库运行以下命令，将已封存备份恢复到**不存在的新目录**。用升级前独立保存的 SHA-256 替换占位值：

```powershell
pwsh -NoProfile -File DOCS/verification/IMP-30/Restore-Bundle.ps1 `
  -Bundle 'E:/Recovery/before-upgrade' -ManifestSha256 '<64位可信SHA256>' `
  -Destination 'E:/Recovery/restored-old-version'
```

3. 从恢复目录启动旧 EXE 和 CLI，并确认实际文件哈希属于上一源版本；用旧配置和旧会话恢复副本验证打开、规则值及 A/B 内容。把快捷方式切回该目录是人工选择，不原位替换正在运行的安装。
4. 将恢复的原 SQL 副本与升级前/IMP-19 备份 SHA-256 逐字节对比，保留 BOM、换行和编码。需要替换当前 SQL 时，先再备份当前文件、停止写入并确认目标映射，然后由用户明确选用已校验的恢复副本。不要从报告反向拼接 SQL；不要把文件恢复视为已撤销数据库改动。
5. 留存旧应用启动、配置/会话读取、SQL 比对结果及候选保留状态。校验失败立即停止，不删除备份、不覆盖目标、不把部分恢复当作成功。

恢复实现拒绝额外/缺失/篡改文件、未知清单版本、重复路径、路径越界、NTFS 重解析点和已存在目标。先在同卷的私有临时目录复制、落盘、复验，再用不覆盖目录重命名提交。失败残留 `.restore-*` 是私有诊断材料，可在人工确认后清理；不提供断电、介质损坏或恶意管理员并发替换路径下的保证。

发布/恢复脚本使用共享异常边界：预期 I/O/校验/取消失败返回非零；未知错误生成 DUMP 并保留错误日志。完整构建是脚本引导前提；SDK/Core 缺失会在执行发布前失败。正式发布前还需项目的签名、分发和批准流程。

回退/会话探针接受相对于调用时工作目录的路径，并在进入子进程前转换成绝对路径。必须传入候选内嵌构建证据对应的同一次 `BuildEvidence`；旧候选不能借用新构建证明。留存 `inputs.json`、`stage-evidence.json` 及其中列出的所有命令输出，缺失或改动均应阻断复核。命令回执中的 `TimedOut=true` 或捕获完成标志为 false 表示失败，即使主进程已返回 0。
