# SqlXmlAnalyzer 2.0.0 / IMP-30 本地候选发布说明

候选编号、源文件指纹及实际二进制以包内 `release-status.json`、`build-evidence.json`、`bundle-manifest.json` 为准。程序集版本保留 2.0.0，不能仅以版本号辨认累积工作树。此包未经签名，状态为 CandidateOnly；正式分发和 M7 完整改善发布尚未批准。请同时阅读 [问题状态](IssueStatus.md) 和 [升级/回退操作单](UpgradeRollback.md)。

## 行为修正

- 多语句计划与多事件死锁分别选择，使用完整语句、算子、对象身份；支持声明范围内的 XML 包装与 XEL 检索。无效 XML/错误根/DTD 不再作为成功分析。
- 输出行与读取行分列；并行、重复执行、残差谓词和本节点属性按已收集事实呈现。缺失成本、优先级和运行指标不再补作已知 0。
- 死锁环共享分析，避免起点重复和重叠环遗漏；界面使用“依赖推演”，不声称快照包含真实时间线。模拟与评分保留假设，不能当作 SQL Server 实测收益。
- SQL 改写先生成提案，再选择、验证、审核和应用。文件写回前验证原件与备份；原件有变、备份失败、提交前取消均阻断。提交后的报告失败会保留真实提交状态。
- 统一报告与本地诊断包先审核固定内容再保存新文件。未知脱敏覆盖范围明确阻断或提示；原始 SQL、配置、会话、日志和 DUMP 不自动匿名。长报告可以滚动到保存操作。
- 旧配置和会话可按支持契约读取；转换另存新副本。未来版本拒绝而保留原件。CLI 输出形状、既有参数别名和既有字段保留。

## 规则与默认限制

IMP-30 未修改任何分析规则或默认严重度。当前目录有 34 个稳定执行 ID；历史配置别名 `RULE_016_WAIT_STATS` 映射到 `RULE_036_WAIT_STATS`。规则严重度仍以随包 `RuleConfiguration.json` 和诊断协议为准，不能和日志等级混用。较早修正可能令原先误判消失，或暴露实际缺失、读取放大和残差问题；升级后不能仅比较警告数量。

TRIM 语义、表变量转临时表、事务回滚、名称与作用域等前提不明时默认限制转换。动态 SQL 和未验证数据库环境不作普遍语义等价保证。CLI `refactor` 默认生成候选，`SourceWritten=false` 不表示已应用；0 退出也不表示 SQL 已修改。

## 支持与升级要求

- 本候选为 Windows x64，自包含 .NET 8 的 GUI 和 CLI。必须保留整个目录，不能只取一个 EXE；配置、库、原生组件和文档都属于清单。构建/发布/恢复脚本需要 .NET SDK、PowerShell 7.4 或更新版本（承载 .NET 8 Core）及相应 NuGet 依赖；运行随包 EXE 不依赖 PowerShell。
- GUI：`gui/SqlXmlAnalyzer.exe`；CLI：`cli/SqlXmlAnalyzer.CLI.exe --help`。默认配置分别位于各自应用目录；显式相对 `--config` 路径仍相对当前工作目录。
- 配置支持无版本及 `ConfigurationSchemaVersion="1"`；会话支持旧 2.0 和当前 2.1，保存为新 2.1 副本。不要把新版写回旧版本原件，不保证旧应用能读新格式。
- JSON 报告为 `IMP22-1.0`，规则运行协议 `1.0`，提案版本 `1`，诊断包 `IMP27-1.0`。报告与诊断包不能代替可恢复的会话或安装备份。
- CLI：成功 0、扫描/阈值失败 1、用法/配置/输出失败 2、取消 130。缺失指标须同时读取状态字段。
- SQL 语义和 DDL 验证覆盖已记录的 SQL Server 2019/2025 LocalDB 场景；不是所有 SQL Server 版本、权限、排序规则、在线生产负载的兼容承诺。

Debug 记录调试、警告、错误、致命信息；Release 只记录错误、致命信息。未知异常生成 Windows minidump 和异常侧车；如果 OS 或存储使 DUMP 无法创建，保留原失败并记录生成失败原因。DUMP 可能包含内存中的 SQL，应按敏感文件保存和审核。

IMP-30 审查修复加强了候选与构建的关联检查：候选包类型、ID、内嵌构建证据、状态中的构建哈希必须相符。回退和会话探针同时记录受测 EXE 的哈希，并绑定命令回执及完整 stdout/stderr。进程退出和输出捕获共用超时期限；捕获不完整不能作为通过。已知证据校验/JSON/I/O 错误按 Error 处理，不生成 DUMP；未分类脚本错误仍生成 DUMP。
