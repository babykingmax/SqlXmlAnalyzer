实施日期：2026-09-10。对应 UI-16，依赖 IMP-09 输入契约、IMP-12 诊断协议及 IMP-22 脱敏报告。当前工作区已有 IMP-23～26 改动，本步未撤销或提交这些修改。

2026-09-10 审查修复：规则版本统一到规则目录，缺失证据补齐 Incomplete/Ambiguous，日志编码失败明确提示 UTF-8。新增 7 项回归，Debug/Release 各 2691 项通过；见[修复说明](IMP-27审查修复与加固说明.md)和[最新验证](verification/IMP-27-hardening/README.md)。文末保留初次实施的验证记录。

## 使用方式

1. 在左侧导航选择“本地诊断数据包”（包裹图标）。计划工作区捕获当前语句/QueryPlan，死锁工作区捕获当前事件。比较工作区或无分析结果时提供元数据包；快照损坏或过期时仍可打开元数据审核窗口。
2. 默认保留“附带脱敏报告”，原始选中 XML、日志、DUMP 均不附带。版本、配置、错误摘要、缺失证据和校验清单为固定内容。可以取消报告正文；原始 XML 需明确勾选，日志和 DUMP 需分别选择本地文件。
3. 点击“生成 / 更新预览”。逐项选择文件，核对其实际文本、字节数、SHA-256 和脱敏状态。文件清单包含 `manifest.json`、`SHA256SUMS` 自身。DUMP 为二进制，仅显示大小、哈希和限制说明；需另用本地调试器查看内存，界面不提供 DUMP 脱敏认证。
4. 点击“保存审核快照为 ZIP”，使用新的文件名。保存不会重新读取输入或附件，不会覆盖已有文件，也不会自动发送。改变选项会立即清除旧预览并禁用保存；保存期间锁定选项，关闭窗口会请求取消。

窗口持有打开时的报告快照。之后切换语句、事件或活动规则配置，不会替换已捕获报告。要收集新的分析结果，应重新打开窗口。附件按点击生成预览时的字节固定，即使原日志随后变化或删除，保存内容仍与预览一致。

## 包结构与生成条件

结构版本为 `IMP27-1.0`，标准 ZIP，全部条目为固定的根目录文件名，绝不使用源文件名或源路径作为归档条目。

| 文件 | 内容 | 默认行为 / 隐私 |
| --- | --- | --- |
| `context.json` | 应用和 Core 程序集版本、规则协议、报告协议、Debug/Release、日志级别、.NET/OS 版本和架构、包时间与报告时间、范围、能力、可验证采集时间/引擎版本、当前操作状态与阶段耗时 | 固定；筛选元数据 |
| `configuration.json` | 报告实际分析配置、当前会话配置、各自 SHA-256 指纹、本版本规则版本/默认严重度及所选报告的规则版本 | 固定；只保留有效的已知规则设置 |
| `errors.json` | 所选报告失败规则的 ID、版本、相对位置、状态、原因码及当前操作失败标志 | 固定；不复制异常消息、堆栈或历史日志 |
| `missing-evidence.json` | 没有报告/配置、配置变化、采集背景未验证、缺少运行时计数、未选择附件等；Skipped/Failed 原因码与 Missing/Invalid/Incomplete/Ambiguous 指标 | 固定；没有采集到的证据不会填成零或成功 |
| `report.json` | IMP-22 同一选中范围的脱敏诊断报告，包括事实、问题、运行记录和结构 XML | 有可用报告时默认附带；脱敏失败阻止整包预览 |
| `redaction.json` | 脱敏策略版本、处理类别计数、未覆盖项计数及限制 | 随脱敏报告；不含处理前样例 |
| `selection.xml` | 所选语句/QueryPlan 或单个事件的原始 XML 快照 | 明确勾选才附带；`RawSensitive` |
| `application.log` | 用户选择的 UTF-8 `.log` 原始字节 | 明确选择才附带；`RawSensitive` |
| `process.dmp` | 用户选择且通过头部/流目录检查的 Windows minidump 原始字节 | 明确选择才附带；`RawSensitive` |
| `manifest.json` | 版本、每个负载文件的名称、字节数、SHA-256、隐私状态及二进制标志 | 固定；列出除自身与校验文件以外的全部负载 |
| `SHA256SUMS` | 每个负载和 `manifest.json` 的 SHA-256 | 固定；不自哈希，完整清单在审核界面可见 |

配置取自报告不可变 `Configuration` 元数据，而不是导出时重新加载配置文件。当前会话配置单独列出，指纹不同时明确标记需重算。原配置 JSON 中未知规则、扩展字段、自由文本与警告正文不进入默认包；相关缺失项说明其被省略。死锁报告或缺少完整计划配置的报告，分析配置显示不可用，不用当前会话默认值冒充。

`RuleVersions` 使用与内置规则执行共用的目录版本；`ReportRuleVersions` 保留分析快照版本，包括禁用规则的记录。取消报告正文不会丢弃快照中的指标缺失状态。只有未分类的规范枚举状态进入 `MetricGaps`，自由文本、数字枚举写法和未定义状态不被当作已确认的指标状态。

采集条件只保留规范数字版本、带明确格式的采集时间、能力枚举等。没有提供的引擎版本、采集时间、服务器负载、SET 选项、权限及参数等，按缺失/未核实记录。操作状态是当前会话状态，可能与较早保留的报告属于不同请求，包内不推断两者关联。

## 隐私与边界

- 默认敏感标记检查覆盖所有文件及清单：原始 XML、SQL、对象名、用户名/主机名、文件名/路径、未知配置内容、原始异常详情和处理前脱敏样例均不自动收集。
- 脱敏报告保留结构、数值、规则和相对定位，不保证匿名，也不等于可以重现原 SQL。未知 XML 脱敏项使当前包准备失败；用户可以取消报告后重新生成元数据包。
- 显式附带 XML、日志或 DUMP 会在清单及包级说明中标明未脱敏。日志和转储可能包含标识符、凭据、路径或内存中的敏感数据。程序不枚举日志/DUMP 目录，不自动挑选最近文件，不把未知错误新生成的转储自动附入当前包。
- XML 仅为选中范围，不包含其他语句/事件、完整原文件或原始 XEL。错误摘要只覆盖所选报告规则失败和当前操作状态；报告快照创建失败详情仅在本地界面显示，元数据包注明报告不可用。空摘要不证明应用从未出错。
- 本步不增加 CLI 参数、网络上传、签名、加密或 DUMP 内容分析。原报告、配置、CLI、规则 ID 和默认严重度兼容行为不变。

## 校验、预算和失败处理

`DiagnosticPackage` 私有持有审核字节，公开只读条目与文本预览。保存先在目标目录下创建仅当前用户可访问的临时目录，完整写出 ZIP 并落盘；再核对包版本、允许的文件名、唯一性、必需条目、manifest、SHA-256 和原审核快照。全部通过后以不覆盖方式移动至目标文件。取消、I/O 错误或校验失败不会发布部分 ZIP，并清理本次临时文件。清理失败会记录日志，保留主操作结果。

校验器 `DiagnosticPackageValidator.Validate(path, token)` 不解压文件到磁盘；按流核对实际解压字节长度，不只信任 ZIP 中声明的长度。新增文件、重复条目、路径穿越、缺失文件、内容损坏、不同的合法包替换审核结果和不支持的 schema 均被拒绝。SHA-256 用于发现损坏与核对字节，不提供来源真实性或防恶意重签保证。

日志上限 2 MiB；每项上限 64 MiB；所有文件累计上限 128 MiB，包含清单与校验文件；最多 11 项。报告继续遵守 IMP-22 自身的内容/编码预算。UTF-8 日志非法编码、空附件、附件增长/缩短、无效 DUMP 头部/版本/流目录、预算超限均属于预期输入或存储失败。大于预算的内容需减少选择；本步不自动截断日志或转储。文件在读取期间同长度改写无法完全检测，但保存仍使用实际预览过的字节。

所有产品操作边界复用 `ExceptionPolicy`：取消写 Warning，其余预期失败写 Error；未知异常写 Critical，并由 `UnexpectedErrorReporter` 生成真实 Windows minidump 和 `exception.json`，同一异常实例去重。首选 `%LOCALAPPDATA%\SqlXmlAnalyzer\dumps`，失败后尝试 `%TEMP%\SqlXmlAnalyzer\dumps`。DUMP/诊断组件失败会明确报告，不能替代原始错误。minidump 检查只验证文件结构，不能保证调试器可完整还原所有内存。

日志继续遵守编译配置门禁：Debug 输出 Debug、Warning、Error、Critical；Release 仅 Error、Critical。运行时 verbose 参数不能打开 Release 的调试/警告日志。新诊断包日志只记录阶段、项数和敏感内容选择标志，不记录成功处理的附件或 SQL 正文。
