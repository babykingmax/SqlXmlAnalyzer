## 比较与兼容边界

SQL Server 能返回未配对的 UTF-16 代理码元，例如 `CAST(0x00D8 AS nvarchar(1))`。它与 `CAST(0x01D8 AS nvarchar(1))` 的原始值不同，不能被 JSON 的替代字符策略合并。新编码按码元逐字节保存，仅改变这类异常 Unicode 值的报告表示；普通字符串、二进制、日期及高精度 decimal 的既有表示保持不变。标签参与行比较，因此不会与普通字符串或二进制发生歧义。

`sql_variant` 的基础类型、精度、小数位和排序规则属于其值语义。当前 SqlClient 的 CLR 值及结果列模式不足以完整还原这些属性，因此本轮选择明确拒绝，而非将不完整信息视为匹配。错误是已知的支持范围限制，不生成未知错误 DUMP，也不签发应用凭据。用户可为调查目的显式查询需要的基础值和 `SQL_VARIANT_PROPERTY`，但这不扩大原始 `sql_variant` 查询的可应用范围。

每份 SQL 保持 256 Ki UTF-16 字符上限。有界读取允许最多 `4 * MaxSqlCharacters + 4` 字节（兼容 UTF-32 与 BOM），随后严格解码并检查实际字符数。不能用字节上限替代字符限制。流长度仅用于提前拒绝；读取循环最多探测上限后的一个字节，处理短读取与取消，不把截断内容交给分析器。旧 `ReadSnapshot(path, token)` 兼容入口仍存在；语义命令和应用流程统一使用新有界重载。`ISqlWritebackService` 与 `ISqlWritebackFileSystem` 的自定义实现需实现新增有界方法，不能通过先无界读取再截断来实现。

写回校验分别以原快照/候选的精确字节长度作为上限。替换确认丢失后，如果无法在有界读取中确认当前内容，会报告提交结果未知并保留恢复证据，不自动覆盖第三方文件。

清理只接受 `SxaSemantic_<GUID N 格式>` 的本轮名字，生产调用始终使用本轮生成的 GUID；不扫描删除其他数据库。清理有独立 30 秒期限，连接超时 10 秒、清理命令超时 15 秒。连接或清理失败记录具体库名，阻止应用；未知失败沿用真实 DUMP 与异常 sidecar，不能用清理异常覆盖主错误。

桌面端直接展示“已写回”“未写回”或“提交结果未知”。对于失败但确认已提交的结果，仍显示已写回并保留错误详情；确认已写回或结果未知后禁止再次选择/应用。静态提案的 `CanApply=false` 契约不变，有限场景验证仍不代表一般等价或性能改善。
