## JSON 兼容性

原有 `MaxSubtreeCost` 数值字段保留。新增 `MaxSubtreeCostState`：

- `Available`：所有算子的开销均为有限非负数，可用作完整最大值。
- `Missing`：没有可用开销（包括无算子）。
- `Incomplete`：部分算子缺少开销。
- `Invalid`：至少一个算子的开销无效。

后三种状态下不得把 `MaxSubtreeCost` 当作完整上限；它只是已知合法值的最大值，没有合法值时兼容值为 0。控制台和 JUnit 文本显示 N/A 与状态。原始扫描 JSON 的隐私说明保持不变，新增字段不使整个扫描结果成为脱敏输出。

1. [Microsoft Double.TryParse](https://learn.microsoft.com/en-us/dotnet/api/system.double.tryparse?view=net-8.0)：.NET Core 3.0 以后，数值溢出可成功解析成正负无穷，不能仅凭 TryParse 的布尔结果认定成本有效。
2. [Microsoft 算子参考](https://learn.microsoft.com/en-us/sql/relational-databases/showplan-logical-and-physical-operators-reference?view=sql-server-ver17)：Clustered Index Scan 的 SeekPredicates 可用于分区索引；有此属性不代表 PhysicalOp 变成 Seek。扫描也不必然读完整个表。

4. [dotnet/runtime v8.0.0 JsonWriterHelper](https://github.com/dotnet/runtime/blob/v8.0.0/src/libraries/System.Text.Json/src/System/Text/Json/Writer/JsonWriterHelper.cs)：官方成熟实现中 ValidateDouble 对非有限值抛出异常，核实源开销导致 JSON 输出失败的原因。
